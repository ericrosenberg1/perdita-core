# Perdita Core: notes for agents

This is the free plugin half of Perdita. It ships in lock step with the Perdita theme, Perdita Pro and the license server. This is the one public repo of the four, so keep host names, server paths and anything else about private infrastructure out of it. A pre-push hook (infra-leak-guard) blocks the common patterns. The release recipe, live-site notes and the full landmine list are in `~/Code/perdita/CLAUDE.md`, which lives in a private repo.

## Brand tokens

Fallback colors and fonts come from the theme's default preset. See "Brand tokens" in `~/Code/perdita/CLAUDE.md`. Never use a framework default like #2563eb.

## Rules that bite

- **One version number across theme, Core and Pro.** Bump with `../perdita/bin/bump-version.sh <version>` (or this repo's copy), never by hand. Labels are -alpha, -beta or -rc only, and the script refuses a downgrade. `bin/build-release.sh` refuses a version the siblings don't share.
- **The `--wporg` build declares plain X.Y.Z** while `PERDITA_CORE_VERSION` keeps the label. The plugin uploader rejects any version with letters, and the 0.19.5 zip declared `0.19.5-alpha`, so that first submission may never have gone in.
- **Keep the `Update URI` header and the updater's foreign-offer guard.** Without them, a directory listing would let WordPress replace self-hosted installs with the stripped directory build.
- **Automatic updates are on by default since 0.19.7-beta, and the owner's choice sticks.** The updater adds Core to WordPress's `auto_update_plugins` list once per site (flag `perdita_core_auto_updates_defaulted`) and otherwise returns WordPress's own value, so the Plugins screen keeps its Enable and Disable link. Never make `auto_update()` return a bool by default: a non-null answer reads as forced and hides that link. `tests/smoke-auto-update.php` pins it.
- **`Perdita_Crypto` here is a copy of the theme's.** Core loads it only when the theme didn't, and a test fails on drift.

## Modules

14 free module ids live in `inc/modules/` (the Pro plugin adds 13). Module state is the autoloaded option `perdita_core` (`modules.<id>`), and the theme's legacy `perdita_settings['modules']` still matters to the theme suite, so test toggles write both.

Decisions that look like bugs but aren't:
- The module-state migration copies the old `features.seo` and `features.forms` flags even when they equal the defaults. It's behavior-preserving, leave it.
- MCP answers an unknown tool name with `-32602`, not `-32601`. The MCP spec's own example and the reference SDK do the same, and an end-to-end test pins it beside `-32601` for an unknown method.
- OAuth option blobs (grants, clients, connections) only change through `mutate_option()`, a per-option database lock. Don't add a plain `update_option()` on them.
- MCP one-click OAuth connect is free in Core with no license check (Eric, 2026-10-12). Its admin section is titled "One-click connect from claude.ai or ChatGPT" and a test fails on a "Pro:" label.

- Forms Turnstile fails open on a secret Cloudflare rejects (`invalid-input-secret`, `missing-input-secret`) and flags `perdita_forms_turnstile_key_error`, which shows the owner an admin notice until a good verdict or a settings save (Eric, item 82, 0.19.10-beta). Forms Pro sets the same flag. A failed challenge on a good secret still blocks, and `perdita_forms_turnstile_fail_open` lets a site fail closed. An unreadable (undecryptable) secret still fails closed, on purpose.
- No heredoc or nowdoc anywhere in shipped PHP. wordpress.org's Plugin Check refuses them, and `tests/smoke-migration.php` fails on one. The cache drop-in template is a list of single-quoted lines in `dropin_source()`. Bump `DROPIN_VERSION` whenever its output changes, or live drop-ins keep the old code.
- Run Plugin Check on the `--wporg` zip before it goes on the Desktop for Eric. 0.19.9-beta shipped 3 errors that would have bounced the upload (0.19.11-beta cleared them).

## Behavior other code relies on

- Backups dumps write every value through `Perdita_Backups::sql_value()`, never bare `esc_sql()`. esc_sql() swaps "%" for $wpdb's random placeholder, and before 0.19.13-beta every dump carried it. A dump starts with `Perdita_Backups::DUMP_FORMAT_LINE`, and `import_database()` turns `{64 hex}` back into "%" in any dump without that line. Pro's differential dumps follow the same rules.

- Caching early serve: `wp-content/advanced-cache.php` is Perdita's only when its first lines carry `Perdita_Caching::DROPIN_MARKER`, and it serves nothing unless `uploads/perdita-cache/early-serve.on` exists. `sync_dropin()` runs on admin_init, on any plugin (de)activation and on save, and never writes over another plugin's file or edits wp-config.php. WP Super Cache's deactivation deletes the `WP_CACHE` line from wp-config.php, so moving off it means adding that line back (`wp config set WP_CACHE true --raw`).
- Caching files: one page is `{sha1 of its URL}{variant suffix}.html` in `uploads/perdita-cache/`, with `.json` (replay headers, then one entry naming the URL), `.gz`, `.stale` (a purge marked it) and `.lock` (a request is rebuilding it) beside it. The drop-in replays only the strings in `.json`, so the URL entry has to stay the last, non-string element. A variant suffix is keyed on the site salt, and the drop-in knows only the shared copy and the phone copy.
- Caching purges: `purge_everything()` (and `purge_all()`, the hook callback) deletes every artifact at once, whatever "serve stale" says. Only a single-URL purge may leave a `.stale` copy behind, and a stale copy is served only while a live `.lock` (30 seconds) sits beside it and for 10 minutes at most. `tests/smoke-caching-parity.php` pins it.
- Caching option purges: `Perdita_Caching::option_affects_render()` decides whether an option write clears the page cache. Outside Perdita, only the allowlist in the `perdita_cache_purge_options` filter purges (site title and tagline, permalinks, front page, reading, date and comment settings, widgets, `theme_mods_*`, site icon and logo, image sizes). A name ending in `*` matches by prefix. Inside Perdita, every `perdita_*` option purges, since most are a module's settings and print in the page, except runtime state no page reads: `perdita_mcp_oauth_*`, `perdita_indexnow*`, `perdita_cache_*`, the Search Console connection (its verification tag lives in the SEO settings, which still purge), and names ending in a runtime suffix (`_queue`, `_lock`, `_token`, `_log`, `_state`, `_db_version`, `_migrated`, and the rest of the list in the method). Before that denylist, an AI client connecting or a queued email emptied the cache for every visitor. The `perdita_cache_option_purges` filter gets the last word on any option. Preload progress lives in `perdita_cache_preload` for this reason. Never store runtime state under `perdita_caching_*`, and never write `perdita_caching_settings` outside a save (the debug log's 24 hour auto-off is computed in `settings()` instead of written back).
- Caching purge stamps: `purge_everything()` writes `purged-all.stamp` (microtime) before it deletes anything, and a single-URL purge writes `{sha1}.purged`. A page that started rendering before a purge and finishes after it is declined through `purged_since()`, so a post that just went private never lands back in the cache. The full purge deletes the `.purged` marks the stamp now covers.
- Caching store rules: a response that sets any cookie is never stored, unless every cookie is on the `perdita_cache_allow_set_cookie` list (for cookies whose value never shows in the page). `DONOTCACHEPAGE` is checked twice, before capture and after render, and either one skips the page. `Cache-Control: no-store` or `private` on the response also declines it.
- Caching drop-in: `DROPIN_VERSION` is 3. The early-serve switch file `early-serve.on` holds a fingerprint (`dropin_fingerprint()`) of the filter values the drop-in was written with. When a front-end request computes a different fingerprint (a filter added only outside wp-admin), `check_dropin_config()` saves the front end's values, deletes the switch, and lets WordPress serve every page until the next admin request writes a drop-in with those values. Multisite keeps early serve off (`is_network()`, filter `perdita_cache_is_multisite`), since every site shares one `advanced-cache.php`.
- Caching saves: `purge_on_save` is `all` by default (a post save clears everything). At `smart`, `post_purge_scope()` clears nothing for a post that was never published, everything when the publish state, title, slug, date, parent, menu order, password, or public terms changed or the type has no public view, and otherwise the post's own URLs and the lists it sits in.
- Caching size cap: `max_size_mb` (default 1024, 0 for no cap, filter `perdita_cache_max_bytes`). `usage.stamp` holds the running byte total, so every store checks one small file. A store that would pass the cap is skipped and schedules garbage collection a minute out, which trims the oldest pages.
- Caching and logged-in visitors: `perdita_cache_allow_logged_in` alone caches nothing. The request also needs a non-empty `perdita_cache_key_variant`, or the page would land in the copy anonymous visitors get. A logged-in response that sets a cookie is never stored.
- Pro codes against the caching extension points listed at the top of `class-perdita-caching.php`. Keep the names and signatures.
- `Perdita_Client_IP::get()` is the one place that reads a visitor address. It trusts CF-Connecting-IP only from Cloudflare's published ranges (list in the class, filter `perdita_cloudflare_ip_ranges`).

- Sales: every amount sent to or read from Stripe goes through `Perdita_Sales::to_minor_units()` / `from_minor_units()` with the currency, never `* 100`. Zero-decimal (JPY), three-decimal (KWD) and whole-unit two-decimal (ISK, UGX) currencies each convert differently. Pro calls these too.
- Analytics: the consent default carries the visitor's stored choice and runs before every `gtag('config')`, with no consent update on page load. `tests/smoke-analytics-order.php` renders the actual head and footer for six settings paths and runs the inline scripts in node. A blank measurement ID with "manage consent for other Google tags" off prints nothing, and a live site's mu-plugin depends on that.
- Analytics adopts Simple Consent Manager's settings once on `admin_init` for a site that never chose a consent model, and unhooks SCM's head script while Perdita's consent layer is on.
- IndexNow: changes queue during the request and go out at shutdown as one cron event. Under WP-CLI they submit inline at shutdown (filter `perdita_indexnow_submit_inline`), and `save_post` at priority 20 is the catch-all for every save path. A published post queues by id and its URLs are built at flush, because the REST controller (and so the block editor) sets categories, tags and meta after `wp_insert_post()` fires the post hooks. Old URLs (unpublish, trash, delete, slug or term change) are still captured before the change. A trashed post submits the permalink it had while published, never the `__trashed` slug WordPress renames it to before `pre_post_update`.

## Switch to Perdita (`inc/switch/`)

Perdita, Switch to Perdita (`admin.php?page=perdita-switch`, manage_options) and `wp perdita switch list|preview|import|undo` move another plugin's settings into a module. Core loads it only in wp-admin, cron, and WP-CLI.

- **Pro builds against this contract.** Add a source with the `perdita_switch_sources` filter: an array of `Perdita_Switch_Source` objects keyed by `id()`. The full method list is the docblock at the top of `class-perdita-switch-source.php`. Keep the names and signatures. A Pro module that isn't one of Core's targets adds its option names through `perdita_switch_target_options` (Undo restores exactly those) and overrides `apply()` with its own sanitize and save.
- **Sources only read.** They never write, rename, or delete the other plugin's options, files, or meta. WP Super Cache's file goes through `Perdita_Switch_PHP_Config`, a tokenizer that accepts scalar and array literals only. Never `include` it.
- **Every value runs through the module's own sanitize** before the preview calls it importable (`Perdita_Switch_Target::check()`), and a list keeps only the items the module stores unchanged. Secrets go through the module's own encryption, show as the last 4 characters at most, and never reach a log.
- **Storage.** `perdita_switch_state` (per source: imported, skipped, deactivated, reactivated, undone, and counts) and `perdita_switch_snapshots` (the target options before the first import, kept across "Import again"). The term batch is the transient `perdita_switch_job` and the cron hook `perdita_switch_batch`, a transient because the page cache purges on any `perdita_*` option write. Term meta `_perdita_switch_from` and `_perdita_switch_wrote` let Undo reverse exactly what the batch wrote. User meta `perdita_switch_dismissed` holds dismissed notices. `uninstall.php` removes every one of these.
- **Deactivate and Reactivate need activate_plugins too**, and Deactivate needs its confirmation box. Caching sources list leftovers (the plugin's advanced-cache.php, its .htaccess block, and a missing WP_CACHE line) and change each only on a confirmed click. Each item carries a `confirm` label that names the backup folder. `before_reactivate()` takes Perdita's drop-in out first, since those plugins refuse to write over another drop-in.
- **Backups never sit beside the file.** Every copy of `.htaccess`, an `advanced-cache.php`, or another plugin's config goes through `Perdita_Switch_Backups::save_file()` or `save_dir()` into `uploads/perdita-switch-backups/`, a folder with index.php, index.html, .htaccess, and web.config guards. Names are `{kind}-{Ymd-His}-{20 hex}.bak`, files are 0600, and a copy only counts once its size and sha256 match. Never a `.php` name, and never a path a visitor can guess. nginx ignores the guards, so anyone who learns a name can fetch that copy: that's why **wp-config.php is never copied**. Adding WP_CACHE saves a `wp-config-line-*.bak` note naming the one line to delete, and the line itself ends `// Added by Perdita`. `save_dir()` skips symlinks and numbers colliding names. The Switch screen lists the copies and has a "Delete backup copies" button. `uninstall.php` keeps the folder, like `perdita-backups`.
- **Editing wp-config.php and .htaccess.** `Perdita_Switch_Leftovers::config_with_wp_cache()` places the line with the tokenizer (top level, statement start, above the "custom values" or "That's all" comment or the wp-settings.php require, never inside a string, braces, or alternative syntax) and refuses any file that already defines WP_CACHE, including a file loaded from the config's folder. `config_blocker()` sends the owner the manual line for DISALLOW_FILE_MODS or DISALLOW_FILE_EDIT, a multisite admin without manage_network_options, a symlinked or unwritable file or folder, or a file another user owns. `strip_block()` cuts a .htaccess block byte for byte (line endings kept) and refuses a block that crosses another block's marker. Both write through `write_atomic()`: temp file in the same folder, permissions copied, rename, read back. Pro can call `strip_block()` and `write_atomic()`. The filters `perdita_switch_wp_config_path` and `perdita_switch_htaccess_path` point the tests at temp copies, and the suite checks the live files never change.
- **Multisite.** Deactivate and Reactivate of a network-active plugin need manage_network_plugins (Reactivate turns a plugin this screen network-deactivated back on network-wide), and every leftover fix needs manage_network_options.
- **The batch** takes the `perdita_switch_batch_lock` option (an atomic add_option, taken over after 2 minutes), books cron before it works, and saves its cursor before each term. An import or undo from another source waits while a batch runs (`busy_with_other()`). Undo warns when the restored options changed after the import (`changed_since_import()`, a hash stored in the snapshot as `after`).
- **Screen hooks.** `perdita_switch_screen_before( Perdita_Switch_Source[] $sources )` after the intro, `perdita_switch_card_after( Perdita_Switch_Source $source, array $state )` inside each card after its controls, and `perdita_switch_screen_after( Perdita_Switch_Source[] $sources )` before the wrap closes. Pro codes against these names.
- **WP Super Cache writes `$cache_enabled = false` when it's deactivated**, so an inactive copy that says "off" leaves Perdita's cache switch alone, and the Reactivate message tells the owner to switch caching back on in WP Super Cache.
- **WP Mail SMTP sends you to its setup wizard** on the first admin page after it's activated again. That's its own behavior, and the Switch screen leaves its data alone.
- Tests: `tests/smoke-switch.php` (registry, caching sources, leftovers, handler, and screen), `tests/smoke-switch-sources.php` (SEO, SMTP, analytics, and security), and `tests/smoke-switch-safety.php` (corrupt and unusual configs, .htaccess cuts, atomic writes, symlinks, the role and nonce matrix, the batch lock, and Undo after later changes).

## Page cache and WordPress's own output buffer

WordPress 6.9+ opens a template enhancement buffer right before the template (`wp_start_template_enhancement_output_buffer()`, inside the page cache's capture buffer) and fills its placeholders, late block styles among them, in that buffer's callback. `Perdita_Caching::write_buffer()` closes every buffer above its own level before reading, then reads its own. Until 0.19.12-beta it read the innermost buffer at shutdown 0, so every cached page lacked WordPress's per-block CSS while the first visitor's copy had it. To see what a visitor really gets, compare a cached fetch (`x-cache: HIT`) with one carrying an unknown query arg, which skips the cache.
